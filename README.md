# Doctor & Patient REST API

## About the Project

This project is a small REST API developed with FastAPI for maintaining basic doctor and patient information.

The application allows doctors to be created and searched using their ID, while patient records can be added and viewed through simple API endpoints.

The main purpose of this project is to practice building APIs in Python, handling request data with Pydantic, validating user input, and returning appropriate errors.

## Technologies Used

- Python 3.9+
- FastAPI
- Pydantic
- Uvicorn
- In-memory Python lists

## What This API Can Do

### Doctor Management

A doctor record contains:

- Name
- Specialization
- Email
- Active status

The doctor API supports:

- Creating a new doctor
- Viewing all doctors
- Finding a particular doctor using the doctor ID

Doctor IDs are generated by the application when a doctor is created.

### Patient Management

A patient record contains:

- Name
- Age
- Phone number

The patient API supports:

- Adding a new patient
- Viewing all patients

```bash

```

```bash
venv\Scripts\Activate.ps1
```

```bash
pip install fastapi uvicorn email-validator
```

## Starting the Application

Run the following command from the project folder:

```bash
uvicorn main:app --reload
```

After starting the server, the API can be accessed at:

http://127.0.0.1:8000

## Testing the API

FastAPI provides an interactive Swagger interface, so the endpoints can be tested directly from the browser.

Open:

http://127.0.0.1:8000/docs

From Swagger UI, you can create doctors and patients and test the GET endpoints.

## Available Endpoints

### Doctors

**POST `/doctors`**

Creates a new doctor and assigns an ID to the doctor.

**GET `/doctors`**

Returns all doctors currently stored in the application.

**GET `/doctors/{doctor_id}`**

Searches for a doctor using the given ID.

If the requested doctor does not exist, the API returns a 404 error.

### Patients

**POST `/patients`**

Creates a new patient record.

**GET `/patients`**

Returns all patients currently stored in the application.

## Validation Rules

The API follows the required validation rules:

- Doctor email must be in a valid email format.
- Patient age must be greater than 0.
- Pydantic models are used to validate request data.
- `HTTPException` is used for proper API error handling.
- A 404 error is returned when a requested doctor ID is not found.
- Doctor `is_active` is set to `true` by default.

## Example Doctor

The API can be used to create a doctor such as:

```json
{
  "name": "Dr. Quar",
  "specialization": "Dermatology",
  "email": "drquar@gmail.com"
}
```

The application generates the doctor ID automatically.

## Example Patient

A patient can be created using:

```json
{
  "name": "shishi",
  "age": 25,
  "phone": "9876543210"
}
```

## Data Storage

This project uses Python lists as temporary in-memory storage for doctors and patients.

No external database is used in this version of the application.

Because the data is stored only in memory, the records will be cleared whenever the FastAPI application is stopped or restarted.

## Error Handling

The API uses `HTTPException` to return meaningful errors.

For example, requesting a doctor ID that does not exist returns:

```
404 - Doctor not found
```
